# DRAFT — TR02 applied network workbench

This is a local, noncanonical training operation adapted from `TR02-NETWORK-PATH`, with M02 as the remediation target. It preserves the seven-semester/21-episode map. It does not implement the entire canonical TR02 facility, DNS/DHCP variants or all certification objectives. The capacity requirement and changed-address exercise are DRAFT authored extensions, not changes to story canon.

The canonical `network-path-lab.mjs` owns an allowlisted in-process device configuration (`training-edge` only), subnet arithmetic, bandwidth allocation, synthetic routing and service consequences, and fresh verification. The actual editable fields are prefix, gateway and reserved Mbps. The allocated block, host demand and decimal kB/s telemetry must be used to select a working configuration. Invalid-but-authorized configurations remain in state until repaired/reset. Unknown fields/targets and noncanonical address encodings are rejected and audited; they cannot execute code.

The foundation configuration needs 27 usable addresses within 10.44.8.64/27 and 22–24 Mbps after headroom/shared-link accounting. Either authored router (.65 or .66) is valid. The changed-address exercise uses 10.44.10.128/27, routers .129/.130 and a 20 Mbps minimum. This is one measured transfer task, not a general transfer/proficiency claim. Default settings are broken. CONFIGURE never means VERIFIED. Each fresh VERIFY recomputes consequences from current config; config attempts clear probe evidence and prior verification.

Protocol fidelity: code actually serializes/decodes IPv4 headers and TCP segments, including ports, lengths, IP checksum and TCP pseudoheader checksum. A fixed modeled established connection carries a plaintext HTTP health request to synthetic port 8080. TCP handshake, retransmission, congestion control, DNS exchange, TLS, routing devices and service execution are simulated; no network packets are transmitted. A generated HTTP response is simulated behavior, not a running service. No fetch, socket, process, shell, credentials or infrastructure access exists in this lab module.

The application adapter keeps existing hex rendering/combat, earned Recon inspection near the telemetry point, Entry same-turn protection of power access, Technical positioning at the relay, AP, threats and extraction. Verified service pauses the service clock through the resolver's explicit `resolveClockStatePhase(state,{advance:false})` option BEFORE clock/escalation/events resolve. Ordinary callers retain identical default behavior. Losing an operative still fails the tactical operation. Technical completion and tactical outcome remain separate.

Evidence records configuration attempts, revisions, observed state, actual probe results, hints, rejected scope requests and reset. Local deterministic replay checks internal consistency, not identity or authenticity. Hints affect the labeled unassisted score; retries are separate. Task completion is not proficiency. No LMS competency, credential or Principles write exists.

Architecture audit: McCluster `lab-recipe.js` compiles plans; it does not provision isolation. TR01 range core is a choice-based systems harness. Existing signed adaptive sessions authenticate coordinate-practice evidence, not this network lab. The building electronics/server lab runtime supplies a stateful SIMULATION precedent, not running equipment. This module belongs to that simulation class. Future hosted execution must follow the existing Worker owner authorization → Core orchestration → disposable isolated compute → trusted verifier → signed evidence/replay path. Recipe metadata alone cannot enforce isolation. No endpoint or competing backend is added here.
